# 旧 Base、Thermal 失败与当前 Base V9 收敛/矩阵对照

取证时间：2026-09-15 23:09–23:10（北京时间）。本地 Git HEAD：`0a03cc452e95d158f36923ceb5210267979b6234`，已有 dirty 工作区保留。本轮只读云端日志、报告和 Slurm；未改变模型、数据、参数、作业或启动求解。

## 结论

两次失败的直接类别相同：Gurobi Barrier `status_code=12 (NUMERIC)`，但尚未证明由同一条约束或同一数据异常触发。旧 Base 后期互补性突然恶化后停滞；Thermal 中途出现数量级极大的跳变，继续约两天半后仍未恢复到跳变前水平，最终数值失败。

新 Base V9 的数值尺度明显改善、早期部分收敛指标更好；矩阵结构和分解计算量只小幅变化，内存峰值并未改善。第97轮仍远未收敛，不支持全年数值问题已解决或完成日期预测。

### 原因可以说到哪一层

确定的是：两者同为数值失败，并共享旧版宽系数/边界范围、年度容量链接8192行缩放、旧水库输入和庞大的长期耦合结构；两者都没有证明可接受解。

合理推断是：这些共有的尺度和结构风险可能是共同背景，问题不只出现在新增thermal块。尚不能把8192缩放、水库块、近零边界、退化或预处理聚合中的任一项称为本轮已证实的唯一根因，也不能断言thermal模块与失败无关。需冻结同一基准做逐项对照才能进一步归因。

官方说明将系数范围列为数值风险线索，而非条件数或失败约束的直接证明；调整容差也不是数值问题本身的修复：[Gurobi 数值问题诊断](https://docs.gurobi.com/projects/optimizer/en/current/concepts/numericguide/modelissues.html)。

## 2. 新 Base 的收敛进展

以下比较同一迭代编号97，避免把新案例早期与旧案例终态直接比较。

| 日志指标 | 旧 Base iter97 | Thermal iter97 | Base V9 iter97 |
|---|---:|---:|---:|
| PInf | 1190 | 433 | 516 |
| DInf | 6.47e-4 | 2.03e-4 | 2.06e-7 |
| Compl | 341 | 167 | 65.3 |
| 绝对原对偶目标差 | 1.0687e11 | 1.2647e10 | 4.8508e9 |
| 相对目标差 | 120.41% | 118.75% | 109.51% |
| 日志累计求解时间 | 138737 s | 120588 s | 128993 s |

新 Base 相对旧 Base 的PInf和Compl均较好，对偶残差小约3141倍；相对Thermal，对偶残差小约985倍、Compl小约2.56倍，但PInf仍高约19.2%。这支持“部分早期指标改善”，不支持“所有指标均更优”。三个模型的行缩放、数据/目标与参数并不相同，上表是日志轨迹对照，不能当作原物理单位QC或严格因果实验。

新 Base iter77→97：PInf 6480→516（下降92.0%），Compl 565→65.3（下降88.4%），绝对目标差3.7132e10→4.8508e9（下降86.9%）。近20轮有明显进展，无旧案例那种灾难性跳变；DInf在小量级波动。纠正此前“从iter0持续下降”的宽泛表述：早期DInf及目标差有上升，不能称全程单调。

当前P=4.21213054e8、D=-4.429599e9，两者符号仍相反，不能当成已认证上下界或论文成本。相对差定义为 `abs(P-D)/max(1,abs(P),abs(D))`，来自舍入日志，不等同于Gurobi BarConvTol内部停止条件。旧两例的灾难性事件发生在366/633轮之后，仅前97轮不足以排除晚期数值困难。

作为同时间辅助对照：约128993求解秒时，旧Base在iter89（PInf2220、DInf1.05e-3、Compl673），Thermal在iter105（PInf320、DInf1.64e-4、Compl129）；结论仍是新Base对偶残差/互补性较好，但并非优于Thermal的所有指标。

新旧还存在明确的研究基准差异：V9使用物理年度行（exponent0），修正水库与库存界、CF/微容量等，2030 DAC关闭、城市流量正则1 CNY/MWh；Thermal保留旧输入、8192行缩放、DAC和0.001 CNY/MWh城市正则，并开启冷热响应。后续科学情景比较应使用同一基准重新配对，不能直接用不同基准的目标差异解释冷热响应收益。
