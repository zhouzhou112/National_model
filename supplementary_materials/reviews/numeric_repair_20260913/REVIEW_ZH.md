## 2. 改动为什么没有消除数值问题

- 两版 input_manifest 中共同的 75 项输入，其记录 SHA256 全部相同，见 `history/input_comparison.csv`。这里是比较归档哈希，不是重新读取全部大型天气文件。历史 `hydro.py` 与修复前本地版本完全一致，差异文件为空。水库库存异常是继承下来的问题。
- 旧版已经有水量释放上界和原生库容上界，不能把这些全部算成后来的新改动。后来增加的“全时段精确零流量”识别是在移除人工小正数，并不是扩大水库数值范围。
- 生产新增的 1/8192 只缩放少量年度容量联结行。它没有改变全球最小系数的来源（小时 CF）或最大系数的来源（DAC 等），Factor NZ 只减少约 0.59%。行缩放在精确算术下等价，但会改变预处理消元、行列平衡和浮点求解路径，无法保证更稳定。
- 缩放行的残差必须还原物理单位。例如缩放后误差 1e-6 对应原行 0.008192 GWh，即 8.192 MWh，不能直接拿缩放误差当物理误差。
- NumericFocus 从 2 降为 1，是减少求解器的数值保护投入。BarConvTol 从 1e-8 放宽为 0.01 只是改变终止判断，没有修复矩阵条件。增加线程能加快某些迭代，也不能保证收敛。Gurobi 官方同样要求先处理模型数值，再考虑参数：[数值参数说明](https://docs.gurobi.com/projects/optimizer/en/current/concepts/numericguide/numeric_parameters.html)。
- 之前在隔离目录尝试过、但未部署的通用矩阵缩放和其他坐标变换，不是本次失败模型的实际配置，不能混在一条因果链里。

**因果边界：** 已证实“原模型不健康、生产改动没有消除源头、当前组合失败”；没有证实某一个参数独立导致全年崩溃。本轮的小样本对照用于区分机制，不能倒推出一次 9 天运行的唯一病态主元。

生产送出设计下的 24h 补充对照：只收紧循环库存，保留原输入和旧 CF/流量阈值，得到 SUBOPTIMAL，原行最大误差 5.5567e-5；不能作为合格修复。最终完整修复 + crossover 的同窗口达到 OPTIMAL，原行最大误差 1.7735e-11，城市与小时检查全部通过。不要把“只改一个界后迭代结束”再误判为通过科学验收。

## 3. 当前模型口径与本次修复

模型仍为 2030 年容量规划与连续 LP 调度；生产尺度为 8760 小时、31 省小时电力层和 337 城年度电量层。风光为 2024 年北京自然年去闰日，水文等其他源年份沿用既有输入契约，不重新拼接时间轴。决策包括建设容量、小时发电/储能/输电及水库库存、发电流量和弃水流量；目标为既有年化系统成本，单位 million CNY，保留原有流量正则项。容量/功率为 GW，小时电量为 GWh，水流量为 m3/s，库存为 m3；水流量与库存数值变量继续使用原有 1000 m3/s 和 1e6 m3 缩放。电力平衡、RUC、排放、安全裕度、梯级时滞与水量守恒等约束未改写。

### 3.1 有证据的库容直接修正

`HydroCHN_00923`，锦屏二级，4.8 GW：`active_storage_gl` 从 **4522.893565 GL 改为 4.96 GL**，即约 45.23 亿 m3 改为 496 万 m3，原值约为修正值的 912 倍。

依据是生态环境部（原环境保护部）竣工验收文件“工程建设的基本情况”，明确给出该站调节库容与装机容量：[环验〔2016〕97号](https://www.mee.gov.cn/gkml/sthjbgw/spwj1/201612/t20161213_368984.htm)。这属于有依据的物理输入修正，可能改变实际调节能力，不列入“微小影响”的清理预算。

输入采用新文件 `data/hydro/repaired_20260913/hydro_stations.csv`；原表未覆盖，并有逐字节备份、修正账本和哈希清单。2030 条电站顺序不变；仅该站的 active storage 及其派生持续时间改变，29 列不变。`v_max_gl/v_min_gl` 留作原始库存来源值，账本明确本次用直接调节库容覆盖 active storage，不伪称历史两列已经修正。生产读取的是 active storage。

其他异常（例如耿达）已列入 `hydro/reservoir_audit.csv`，没有用未经确认的调节时长或百分位统一替代全国库容。仍需核实其真实参数，不能宣称全表工程参数已经逐站认证。

### 3.2 循环库存的等价范围收紧

当前水库库存仅以时序差分和 `[0, S]` 边界进入模型，无给定绝对期初库存、无库存决定水头的关系。因此，对任意可行循环轨迹 `V`，`V-min(V)` 保持原发电、泄流和逐小时水量守恒不变。该轨迹的幅度不超过周期内全部入库水量。

新上界为 `min(原 active storage, 周期总入库水量的安全上界)`。梯级按拓扑传播上游全年水量上界并计及传递比例，不能只看下游本地来水。实现 `cispo_model/numerical_cleanup.py`，不增加变量、不指定某一小时库存为零。保留容量与调度可行域的投影；绝对库存轨迹因消除常数偏移而不同。

原输入全年审计有 620 个水库，其中 140 个可收紧；最大库存数值上界对应的物理库存从 447.80 亿 m3 降至 184.82 亿 m3。该审计单独保留原物理输入，以免把源修正与等价变换混淆。经本地来水、库存和上游传水安全上界共同证明为精确零的小时，不再人为补上 1e-12 的泄流上界；包括梯级电站。这是精确零识别，不是另设小数阈值。

最终配置另做了完整 8760 小时水文数组复核，见 `hydro/repaired_full_year_summary.json`：锦屏二级实际加载为 4,960,000 m3；其余仍可进行循环库存收紧的电站为 139 个。水量平衡本地入流 RHS（million m3）最小正值从旧全模型水库来源的 2.522818e-7 提升至 3.600018e-5，最大值 50.582704；正本地流量没有低于 0.01 m3/s 的记录。全年释放流量上界数值范围为 8.958436e-4～15297.147939（1000 m3/s）。本项仅审计水库数组，未构建全年 LP，不能称为全年 presolve 验证。

### 3.3 有单位、有预算的毛刺清理

| 处理 | 阈值 | 全年影响上界 / 数量 |
|---|---|---|
| 风光、波浪和径流式水电 CF | 正 CF 小于 1e-4 置零，原阈值为 1e-6 | 在全部站点技术容量上限下合计少 6.101519 GWh；风电和波浪无新增清理 |
| 水库分配、生态扣减及梯级协调后的本地流量 | 0 < q < 0.01 m3/s 置零 | 54,945 站时；658,097.806 m3；含下游重复发电效应的能量上界 0.278072 GWh |
| 新增容量剩余空间 | 小于等于 1e-8 GW 归零 | 新增影响 5 个站点，合计 1.321 W |

6.101519 GWh 是全部技术上限容量的潜在资源损失，不是已求得的真实发电损失。径流式水电相对本技术潜在电量损失约 0.000696%；集中式光伏约 0.00000767%；分布式光伏约 0.00001035%。水库本地直接影响约 0.159667 GWh，0.278072 GWh 已包含其下游上界，不能二者相加。

这些是资源输入误差预算，不是最优装机或最优成本变化的严格上界；不能由它们推出所有规划决策必然不变。有依据的库容纠错与循环库存范围收紧也必须区分。

清理仅作用于已明确来源和单位的系数/数据，不采用全矩阵“小于某值就删”的做法。小的既有容量和有明确用途的成本项没有因绝对数值小而自动删除。水文源 NetCDF 保留，删除水量在读入审计中明确记录，不回灌其他小时或站点。

## 4. 配置和验证边界

新配置：`config/optimization_2030_numeric_repaired.json`，恢复原物理量年度行、NumericFocus=2、BarConvTol=1e-8，采用上述修正与清理。先用 Crossover=0 / SolutionTarget=1 独立验证 Barrier 数值修复，再采用已有的 Crossover=2 / CrossoverBasis=1 / SolutionTarget=0 路线清理退化内点解，检查完整业务验收。新配置选择后一组合，结果见验证表，不能混称为“旧版原参数全部恢复”。它的科学基准 ID 与旧 Base 不同，不能直接把新 Base 与旧 Thermal/EV/Full_Flex 当作同基准的最终情景差值。旧默认配置仍可复现。

新配置中 8 线程、8 GB SoftMemLimit、900 秒是**本地验证预算**，不是服务器全年投产参数。最初 168h 完整测试的 600 秒预算在 crossover 最后清理阶段触发 TIME_LIMIT；保留失败记录，只将该验证补至 900 秒，不再改模型。本轮没有重新提交全年作业，没有停止或改动运行中的 Thermal。

测试结果见同目录 `probe_summary.csv`、`VALIDATION_ZH.md` 及 `probes/*/result.json`。初测采用 `compute_max_cf=False`，送出设计 CF 置 1，仅作为同条件结构对照；带 `_fullcf` 的复核采用 `True`，按生产规定扫描全年 CF 计算送出设计。二者不能混成一组性能比较。所有局部窗口都在窗口内闭合库存循环，不能用局部最优容量代表全年规划结论。

原始矩阵残差通过 `A @ x` 独立重算；同时调用既有物理导出检查。不能把 Gurobi 的 OPTIMAL 标签或“没有大系数警告”单独当作模型健康证明。报告保留未通过的测试与导出失败信息，不隐藏失败。

历史完整 MPS 审计还表明：全年最大变量界约 362,809 的来源是 DAC 全局注入上界，不是水库库存。本次 24 小时配对试验的最大界从 44,780 降至 994，不能外推成“全年所有变量最大界也降至 994”。目标中的 1e-6 省内流量惩罚保留；小窗口通过不能替代全年 presolve 与原物理单位验收。
